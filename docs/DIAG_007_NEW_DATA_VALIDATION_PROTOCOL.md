# DIAG-007：新数据验证协议设计（New Data Validation Protocol）

> **性质：协议设计文档 —— 无数据接入、无实验执行、无运行产物、无注册条目。**
> 目的：在真实 xG/xGA、首发阵容、伤停数据未来接入**之前**，预先锁定验证方案，
> 杜绝未来的数据驱动过拟合与事后调参。
> 纪律：不修改生产模型与 config；不添加 Agent；不调参；不以提升指标为目标做优化；不进入 V1.3。
> 继承：V1.2 冻结基线、DIAG-005 探针框架（冻结 Elo / 无训练 / 无权重 / 无参数）、
> DIAG-006 数据价值评估结论（xG→阵容→伤停的获取优先级）。

---

## 0. 核心原则（预注册，不得违背）

1. **单一冻结基线**：一切探针只以冻结 Elo 概率为基线（380 场，Brier 0.6310，不可变）。
2. **无训练 / 无权重 / 无参数**：探针是纯条件频率估计，没有任何可拟合的自由度。
3. **时间戳门槛**：任何新数据记录，没有「生成/公布时间戳 < kickoff」就不可用，
   无法确认时间戳的记录一律排除。
4. **不可变版本**：数据一旦通过接入标准即冻结为版本（带 fingerprint），探针只读该版本；
   任何更新/修正产生新版本，必须重跑该源探针。
5. **禁止事后调参**：所有阈值、分箱、编码、判定规则在接入数据**之前**锁定；
   结果不得反哺实验设计。

## 1. 新数据接入标准

### 1.1 xG/xGA 接入标准

| 维度 | 标准 |
| --- | --- |
| 来源 | 单一可复现供应商 + 明确模型版本（如 StatsBomb / Understat / FBref·StatsPerform 之一），**禁止混源**；记录供应商名、模型版本号、字段语义（是否含点球、是否含乌龙）。 |
| 时间戳 | 每条 xG 记录必须带 `xg_generated_at`；同时存档 `kickoff`。 |
| kickoff 前可用性 | 硬性：预测输入只允许 `xg_generated_at < kickoff` 的**赛前快照版本**；赛后重算/修正版本作为独立版本隔离，禁止混入。 |
| 缺失处理 | 某场次缺 xG 或缺赛前快照 → 该特征置 `None`，探针走 elo-only 回退（继承 DIAG-005 回退链），**禁止插补/回填/借队**。 |
| 数据版本管理 | 每个（赛季 × 供应商 × 模型版本）生成一个不可变 data_version（沿用项目 fingerprint 机制）；赛前快照与最终版本均存档供泄漏审计。 |

### 1.2 首发阵容接入标准

| 维度 | 标准 |
| --- | --- |
| 公布时间记录 | 每场记录 `lineup_published_at`（英超 2024-25 起规则为赛前 75 分钟，以实际记录为准）；`lineup_published_at < kickoff` 才可用。 |
| 首发变更处理 | 记录 `lineup_last_change_at`；热身受伤等**赛前末刻变更**若 `last_change_at < kickoff` 且可捕获则用最终版本；否则该场次标记 `unstable_lineup=True`，其 lineup 特征降级为 None。 |
| 替补影响 | 首发 11 人 + 替补名单均存档；**替补影响不进入主 probe**（预注册为后续扩展），避免过度设计。 |
| 缺失处理 | 名单缺失或公布时间缺失 → 特征置 None → elo-only 回退；整源缺失率 > 10% → 该源整体 INSUFFICIENT EVIDENCE。 |

### 1.3 伤停接入标准

| 维度 | 标准 |
| --- | --- |
| 确认时间 | 每例伤停带 `injury_confirmed_at` 与 `return_expected`；`injury_confirmed_at < kickoff` 才算「赛前已知伤停」。 |
| 严重程度编码 | 预注册三档：`missing_confirmed`（确认缺阵）/ `doubtful`（存疑）/ `available`（可出战）。**只有 `missing_confirmed` 与 `available` 进入主 probe**；`doubtful` 单独一档，仅作敏感性。 |
| 不确定新闻排除规则 | 无 `confirmed` 布尔、无时间戳、含「可能/传闻/预计」语义的记录一律排除（**禁止模糊新闻代理**，继承 DIAG-006）；排除规则可机检：`confirmed != true` 或 `injury_confirmed_at` 缺失 → 不纳入。 |

## 2. 验证实验设计（继承 DIAG-005，阈值保持不变）

| 元素 | 规格（与 DIAG-005 一致，不改变） |
| --- | --- |
| 基线 | 冻结 Elo（不可变）。 |
| 单源 probe | 条件校准探针 `(Elo 概率动态三分位 × 源特征动态中位数)`，展开窗口经验条件频率。 |
| 回退链 | (elo×s) 计数 < 20 → elo 分层计数 < 20 → 原 Elo 概率；最小历史 30 场。 |
| 组合 probe | 仅对**通过单源阈值**的源做两两组合（联合网格 3×2×2）；只报「组合 ΔBrier vs 两单源 ΔBrier 之和」的方向，不判定、不选择。 |
| permutation test | seed 20240101，10,000 次；主置换 = **源特征值重排**（实现 H0「源无 Elo 外增量」）；次级置换 = 结果向量重排（透明参考，已知 anti-conservative）。 |
| split-half | 前/后 190 场 ΔBrier 均 < 0 才一致。 |
| Murphy 分解 | 单结果信息项 C = mean((A−E)(E−1))；C<0 才与「有增量」方向一致；C≈0 判为 Elo 重复。 |

### 成功标准（**保持 DIAG-005 不变，确认如下**）

> 仅当同时满足：**`ΔBrier(probe − elo) ≤ −0.003`** 且 **置换 p < 0.0071**（Bonferroni，7 候选）
> 且 **split-half 一致** → 标记「具备 Elo 外增量（EVIDENCE）」；
> 否则一律 **INSUFFICIENT EVIDENCE**。

新增两条效力门槛（预注册，防止小样本假增益）：

1. **最低有效样本**：某源在「非空特征场次」< 100 场时，直接判 INSUFFICIENT EVIDENCE（不做检验）。
2. **回退上限**：某源走 elo-only 回退的场次占比 > 30% 时，结果仅作参考并降级 INSUFFICIENT EVIDENCE。

## 3. 数据接入后的实验顺序

| 步骤 | 内容 | 单源特征（预注册） | 门控 |
| --- | --- | --- | --- |
| **D7.1** | xG 单源验证 | `xG 差 = 主队滚动 xG(10 场) − 客队滚动 xG(10 场)`，严格 <t | 数据先通过 §1.1；产出独立报告 + 注册条目 |
| **D7.2** | Lineup 单源验证 | `缺阵指标 = 首发确认缺阵人数（相对全勤基线）` + `核心缺阵二值（门将/最佳射手）` | 数据先通过 §1.2；独立判定 |
| **D7.3** | Injury 单源验证 | `赛前确认伤停人数（missing_confirmed only）` + `关键球员伤停二值` | 数据先通过 §1.3；独立判定 |
| **D7.4** | 组合信息验证 | 仅对 D7.1–D7.3 中**通过单源阈值**的源做两两组合（联合网格） | 至少 2 源通过才执行；否则记录「无可组合源」 |

- 每步独立判定，一源失败不阻塞其他源；顺序按 DIAG-006 优先级（xG→lineup→injury→组合）。
- 每步产物预注册：`backtest_output/diag_007_*/`（probes.json / stats.json / 注册条目 / 报告）。

## 4. 风险分析

### 4.1 新数据是否只是 Elo 的重复信息？
- **xG**：与进球率/射正率相关（DIAG-005 已证后者无增量）→ 真实 xG 可能仍与 Elo 的历史
  结果信息高度重叠。缓解：条件校准探针在 Elo 分层**内**测残差增量 + Murphy C；
  **C≈0 即判为 Elo 重复，不强行宣称增量**。
- **阵容/伤停**：与 Elo **结构性正交**（Elo 无任何比赛级人员信息）→ 重复风险低；
  但仍以 C 与置换 p 为准，不预设结论。

### 4.2 是否存在赛后信息泄漏？
- 泄漏源：xG 赛后重算、阵容赛后补录、伤停「事后确认」。
- 缓解：§1 的硬性时间戳门槛 + 赛前/赛后版本隔离 + 快照审计 + 缺失率审计；
  无法确认时间戳的记录**一律排除**，探针评估只用 <t 历史（零泄漏构造）。

### 4.3 是否因样本量不足产生假增益？
- 单赛季 380 场，关键缺阵/伤停样本尤其稀疏。
- 缓解：三重预注册控制 —— 置换 p（10,000 次）+ split-half + Bonferroni（0.0071），
  再加 §2 的两条效力门槛（最低 100 场有效样本、回退占比 ≤30%）；跨赛季数据（DIAG-006 源 4）
  用于逐步增效力，但跨赛季结论需走赛季迁移检查。

### 4.4 是否因供应商变更导致分布漂移？
- 供应商/模型版本/采集口径变化会改变特征分布。
- 缓解：§1 的不可变版本 + fingerprint；漂移检测 = 冻结版本内 split-half +
  跨版本一致性报告；**任何版本变更必须重跑该源探针并对比，不默认沿用旧结论**。

---

## 5. 结论

本协议在数据接入前锁定：接入标准（§1）、验证设计（§2，与 DIAG-005 完全一致）、
实验顺序（§3，D7.1→D7.4）、风险控制（§4）。**成功标准保持 DIAG-005 不变
（ΔBrier ≤ −0.003、p < 0.0071、split-half 一致）**，并新增两条效力门槛防小样本假增益。

本协议不获取数据、不接入数据、不修改模型、不添加 Agent、不调参、不以指标优化为目标。

*协议设计完成，按要求停止。*
