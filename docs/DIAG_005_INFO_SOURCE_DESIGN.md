## 0. 方法论总纲：条件校准探针（无训练、无参数、无权重）

DIAG-003/004 已确立：融合结构不是瓶颈（DIAG-003），Agent 无 Elo 外信息且其偏离为反信息
（DIAG-004：Murphy C>0、McNemar 反向显著）。因此 DIAG-005 **不触碰 Agent 流水线**，
直接在 **Elo 概率基线之上**逐源测量增量。探针构造如下（全部预注册）：

1. **基线**：冻结 Elo 概率（380 场，确定性）。
2. **源特征**：对每个候选源 s，用**严格 walk-forward（date < kickoff）** 构造标量特征
   `x_s(t)`（主队侧、客队侧或差值，逐源预注册，见第 2 节表）。
3. **离散化**：`x_s` 分 2 bins，阈值 = **截至 t−1 的展开窗口历史中位数（动态、无泄漏）**；
   历史 < 30 场时该源退化为单 bin（即不使用该源）。
4. **Elo 分层**：对每个结果（home_win/draw/away_win），Elo 该结果概率分 3 bins，
   边 = 截至 t−1 的展开窗口三分位（动态）。
5. **探针概率**：对 t 的每个结果，取「(elo_bin × s_bin) 网格」在 t 之前场次的
   **实际结果频率**（经验条件频率，3 结果按行归一化）——
   **纯计数估计，无任何参数拟合**。回退链（预注册）：
   (elo_bin × s_bin) 计数 < 20 → (elo_bin) 频率 → 仍 < 20 → 原 Elo 概率。
   早期赛季回退场次**保留在评估中**（不挑样本）。
6. **评价**：对全部 380 场计算探针的 1X2 概率 →
   `ΔBrier = Brier(probe) − Brier(elo)`（三类 Brier，口径同冻结 `full_metrics`）、
   `ΔLogLoss`、以及 DIAG-004 S2 同式的 **Murphy 信息项 C**（实际结果单结果分解）。
7. **推断**：置换检验（实际结果向量随机重排，**seed 20240101，10,000 次**）
   对 ΔBrier 与 C 各给单侧 p（H0 = 该源无 Elo 外增量）。
8. **小组合探针**（预注册，仅对通过单源阈值的源计算）：两两组合 = 3×2×2 联合网格的
   条件频率；只报告「组合增量是否超过两单源增量之和」的**方向**（增量可加性），
   不做任何选择/优化。

## 1. 候选信息源逐项设计（每源：理论假设 / 数据需求 / 泄漏风险 / 指标 / 阈值）

通用成功阈值（先列，逐源不再重复）：**`ΔBrier ≤ −0.003` 且置换 p < 0.05
（Bonferroni 按源数 7 → α=0.0071）且 split-half 一致**（前 190 场与后 190 场的
ΔBrier 方向均为负）。同时报告 C 与 ΔLogLoss（描述性）。

### 1.1 xG / xGA（当前只能代理）

- **理论假设**：预期进球比实际进球/射门数量更早、更稳地反映真实攻防强度
  （过程信息优于结果信息）；若假设成立，xG 差应提供 Elo 外的真实增量。
- **数据需求**：真实 xG 需供应商级数据（含生成时间戳）。
  **当前 DATA_UNAVAILABLE**（数据层无 xG 字段）。
  预注册代理 `xG_proxy = 0.5×norm(rolling 进球率进攻) + 0.5×norm(10 场射正率)`，
  主客两队差值；norm = 展开窗口 z 标准化（动态）。
- **泄漏风险**：代理本身无泄漏（严格 <t）。**未来引入真实 xG 时必须校验时间戳 < kickoff**
  （多数公开 xG 按完赛发布，事后更新为高风险泄漏源——若无法确认时间戳，标记不可用）。
- **指标**：通用框架 ΔBrier/C/ΔLogLoss；**代理结果只代表代理，不冒充真实 xG 结论**。
- **成功阈值**：通用阈值。

### 1.2 射门质量（转化效率）

- **理论假设**：每脚射门的威胁度（转化）优于射门总量；Elo 只用了进球结果，
  转化效率是 Elo 外的过程信息。
- **数据需求**：shots / SOT（**已存在**），10 场窗口 walk-forward。
  特征 = `(主 SOT/shots − 客 SOT/shots)`，来自既有 `rolling_match_stats`
  （sot_for/shots_for）。**零新 ETL。**
- **泄漏风险**：无（严格 <t 窗口）。
- **指标/阈值**：通用框架。

### 1.3 射正率（绝对量）

- **理论假设**：SOT 数量是进攻效率最稳健的单一统计。
- **数据需求**：已存在（rolling_match_stats.sot_for）。特征 = 主客 SOT 差（10 场窗口）。
- **泄漏风险**：无。
- **指标/阈值**：通用框架。
- **重复计分注记（预注册）**：1.2 与 1.3 高度相关；若两者都通过，仅报告
  ΔBrier 更强者为主证据，另一个列为敏感性，不作双份证据。

### 1.4 赛程密度

- **理论假设**：疲劳/轮换随拥挤赛程折损表现；Elo 不包含赛程信息
  （DIAG-004 的信息缺失型代理已提示该方向，但当时与低把握区混在一起）。
- **数据需求**：congestion_14d（**已存在**，重建层有主客两值）。特征 = 主−客差值。
- **泄漏风险**：无。
- **指标/阈值**：通用框架。

### 1.5 主客场因素（时变残差）

- **理论假设**：主场优势随时间/联盟状态漂移；**Elo 基线只含固定 +60 主场项**
  （baselines.py 已确认）→ 时变主场残差可能提供增量。
- **数据需求**：主客标记（venue 字段全空，用主客标记代替）。
  特征 = 主队指示符（{主, 客} 两 bin，条件频率网格自动估计其时变效应）。
- **泄漏风险**：无。
- **指标/阈值**：通用框架；**负对照**：冻结 home_advantage 基线 Brier 0.6659 ≫ Elo 0.6310，
  单源很弱，预期增量小——若通过阈值反而是强发现；若未通过，作为探针框架的
  「无效应对照」一并报告。

### 1.6 阵容稳定度

- **理论假设**：轮换/首发变动影响短期战力（信息在 Elo 中不存在）。
- **数据需求**：首发名单 + **公布时间戳**。当前 lineup 字段全空
  （`home_lineup_status=unknown`，`lineup_observed_at=None`）→
  **DATA_UNAVAILABLE，无可注册代理** → 本阶段不测。
- **泄漏风险**（未来）：必须使用公布时间戳 < kickoff 的名单；赛后补录名单 = 泄漏。
- **指标/阈值**：暂不适用；本阶段仅输出数据需求规格。

### 1.7 伤停信息

- **理论假设**：核心缺阵改变实力（Elo 反应滞后或无反应）。
- **数据需求**：伤停名单 + 公布时间戳。当前 `injuries_known=[]` 全空 →
  **DATA_UNAVAILABLE，无可注册代理** → 本阶段不测。
- **泄漏风险**（未来）：同 1.6（时间戳门槛）。
- **指标/阈值**：暂不适用。

### 1.8 纪律外记录（不测，但如实披露）

- `closing_odds`（Avg 盘、kickoff 时间戳）**已存在于数据层**；项目 no-market 纪律
  （`market_data=false`）→ 本设计**排除**。若未来用户明确解除该约束，市场赔率
  是「人类集成信息」的最强候选探针（单独另行设计）。

## 3. 评价指标与成功阈值（统一）

- **主指标**：`ΔBrier(probe − elo)`（三类 Brier，380 场）+ 置换 p（seed 20240101，10,000）。
- **次指标**（描述性）：Murphy 信息项 C（应与 ΔBrier 方向一致：C<0 ⟺ 增量真实）、
  ΔLogLoss、split-half 一致性（前/后 190 场 ΔBrier 均 < 0）。
- **成功阈值（预注册）**：`ΔBrier ≤ −0.003` 且 `置换 p < 0.0071`（Bonferroni，7 源）
  且 split-half 一致 → 判定「该源具备 Elo 外真实预测增量」。
- **失败但方向为正** → 记录方向；**p ≥ 0.0071 或 split-half 不一致** →
  「INSUFFICIENT EVIDENCE」。
- **对照锚点**：本探针框架先用 1.5（主客场）验证 —— 若框架在已知无效应源上
  不产生假阳性，框架可信度成立（负对照报告）。
- **组合探针**：仅报告方向性（组合增量 vs 两单源增量之和），不判定、不选择。

## 5. 重点回答：「下一步应该寻找什么信息，而不是增加什么 Agent」

按本设计预注册的判定逻辑，执行期报告将把信息源归为三档：

1. **当前可测、应优先验证（零成本）**：射门质量 / 射正率 / 赛程密度 / 时变主场因子
   —— 数据已在数据层，DIAG-005 直接给出「哪些已有信息源值得进入任何后续系统的输入」。
2. **需要获取数据（获取建议，而非 Agent 工作）**：
   - 供应商级**真实 xG/xGA**（含时间戳）→ 替代 1.1 的代理；
   - **首发名单与伤停**（含公布时间戳）→ 使 1.6/1.7 从 DATA_UNAVAILABLE 变为可测。
3. **按纪律排除（等待解除约束）**：市场赔率（数据已存在）。

**结论性方向**：DIAG-001~004 的累积证据（信息重复 → 乘性放大不成立 → 结构非瓶颈 →
Agent 无 Elo 外信息且偏离为反信息）一致指向：**问题在信息源，不在 Agent 数量或组合方式**。
下一步的投资方向是**获取并验证新信息源**（xG、伤停、阵容、必要时市场），
而不是增加或调整 Agent。
